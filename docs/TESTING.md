# 2D跑酷测试清单

[返回项目首页](../README.md)

此清单用于每次发布回归，勾选项由实际验证后填写，不代表当前已经自动通过。

## 文件和启动

```bash
node tools/check-site.mjs
node tools/test-boot.mjs
node --check web/boot.js
node tools/serve.mjs 8081
```

- [ ] 标题只显示“2D跑酷”。
- [ ] 配置、loader、unityweb和样式请求无404。
- [ ] 加载完成后入口画面正常，中文按钮可见。
- [ ] 下载失败时显示错误，不永久停留在加载条。
- [ ] 首次点击后音频可播放，键盘获得焦点。
- [ ] 窗口缩放后入口、跳跃和暂停按钮仍能操作。

## 输入与流程

- [ ] 名称为空、只有空格或正常名称时均能开始。
- [ ] 开始按钮的点击不会误触第一跳。
- [ ] 空格、上方向键和UI跳跃分别有效。
- [ ] 键盘与UI同帧输入、连续点击、落地瞬间输入不产生双倍施力。
- [ ] 跨两个地块接缝时接地判断正确。
- [ ] 空中输入的行为符合当前跳跃规则。
- [ ] 暂停时地形和分数停止，恢复后继续。
- [ ] 暂停后重开或返回入口，新场景不冻结。
- [ ] 碰到危险物只结算一次，结果和当局分数对应。
- [ ] 连续重开三局，生命、计分、输入门禁与UI状态不残留。

## 地形与难度

- [ ] 有效地块持续补充，出屏地块不无限积累。
- [ ] 无效预制体被过滤，只有一个候选时仍能生成。
- [ ] 相邻高度差遵守配置，重复选择抑制没有死循环。
- [ ] 在初始速度与最高速度下测试平台边缘、连续高度变化和金币位置。
- [ ] 记录不可达组合的地块序列、随机种子和速度，便于后续完善生成器。
- [ ] 长时间游玩时观察GC、内存和帧时间，而非只看平均FPS。

## 分数与记录

- [ ] 收集金币增加数量和分数，同一个金币不重复计入。
- [ ] 暂停期间不累计有效游玩时间与距离分。
- [ ] 新纪录更新最高分，低于纪录的成绩不覆盖最高分。
- [ ] 刷新同来源网页后检查本地记录。
- [ ] 隐私模式、网站存储被清理时，能按无记录状态正常开始。

## 记录要求

记录构建提交号、浏览器、窗口大小、操作步骤与日志。先通过静态检查，再通过浏览器加载，最后验证玩法组合。文件检查脚本无法证明地形必然可达，也不能代替真实输入和结算测试。
