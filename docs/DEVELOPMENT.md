# 2D跑酷开发记录

[返回项目首页](../README.md)

## 1. 开发顺序

项目使用Unity 2022.3.62f3c1开发。先完成跳跃和地形滚动，再加入金币、障碍和分数，最后接通玩家名输入、暂停、结算和重开。

开发时主要围绕跳跃响应、地形衔接和状态切换调试，确保一局游戏能从开始持续运行到结算，再进入下一局。

## 2. 模块职责与调用关系

| 模块 | 职责 |
| --- | --- |
| LoginSceneController | 玩家名输入、开始标记和场景跳转 |
| GameManager | 游戏状态、难度、计分、暂停、结算数据与UI |
| PlayerControl | 跳跃、接地动画、危险碰撞与死亡 |
| GroundControl | 地形滚动、预制体筛选、随机选择与高度约束 |
| CoinControl | 金币触发、收集反馈与计分通知 |
| BgControl | 背景运动 |
| AudioManager | 音频管理与播放 |
| GameOverSceneController | 本局结果、最高分展示与重开 |

```text
LoginScene -> SampleScene -> GameOverScene
                   |
                Playing <-> Paused
                   |
                GameOver

键盘 / UI -> PlayerControl.Jump -> 刚体与动画
GameManager.SpeedMultiplier -> 地形滚动与距离分
金币 -> AddCoin -> HUD -> 结算数据保存
```

## 3. 开发过程中的关键处理

### 键盘与UI跳跃

键盘和UI都需要控制跳跃，我把它们接到同一个Jump方法，统一检查游戏状态、接地和生命，再清除竖直速度并施力。排查“按下去没反应”时，先确认输入有没有进入Jump，再检查是哪一个条件阻止了起跳。

场景切换时还需要隔开开始按钮与玩法输入。当前通过unscaledTime设置约0.18秒的解锁时间，集中在开始游戏时处理。同帧双输入和平台接缝的接地判断，放在下一步手感优化中继续完善。

### 暂停与重新开始

暂停不仅影响画面，也影响地形滚动、计分和跳跃。我让这些逻辑读取GameManager状态，只在Playing时继续执行；暂停时切换状态并设置timeScale，恢复时一起还原。

重开和返回入口也显式恢复timeScale。这样从暂停菜单切换场景后，新场景可以正常运行，结算和输入状态也能重新初始化。

### 随机地块的筛选与衔接

地形生成先过滤标记或碰撞条件不符合要求的预制体，再从候选中随机选择。为减少连续出现同一地块，选择时设置有限次数的重抽，候选较少时也能结束选择。

高度变化同时受全局范围和maxHeightStep限制。出屏后补充下一段并销毁旧实例。接下来准备将平台间隙、宽度与当前速度一起纳入可达性判断，让随机组合更符合实际跳跃范围。

### 死亡、计分与结算

角色死亡入口先检查生命，首次处理后将生命归零，再通知GameManager结束游戏，避免多次碰撞重复进入结算。距离分随时间和速度倍率累计，金币通过AddCoin记录，结束时统一计算整数总分。

PlayerPrefs保存玩家名、最高分和本局结果。结算时先比较最高分，再写入当局分数与金币数，GameOverScene读取这些数据展示。新的一局重新初始化角色生命和游戏状态。

### 构建后的中文与UI显示

按钮文字在编辑器里可见，打包后仍需要检查字体和资源引用。调试时直接打开构建版本，确认开始、暂停、重开等按钮的文字完整，再检查不同窗口比例下的位置和点击区域。

## 4. 打包与验证

1. 使用Unity 2022.3.62f3c1及对应的WebGL Build Support。
2. 检查角色、地形预制体、UI事件和音频引用，确认Console无编译错误。
3. 将LoginScene、SampleScene和GameOverScene按顺序加入Build Settings。
4. 分别导出Windows和WebGL版本；WebGL通过HTTP加载运行。
5. 在构建版本中检查名称输入、开始、跳跃、金币、暂停、死亡、结算和重开，再连续游玩多局观察地形衔接与状态重置。
